## What Phases 2 and 3 added

- **`factory/options.tsv`**: 24 options, each with default, choices, scope (service or ops),
  how it takes effect (conf, `workflow:<file>`, `var:<NAME>`), whether onboarding asks, what
  it does, how to change it later. Seeders write each repo's `.xal/factory.defaults` from it;
  `scaffold/common/scripts/driver/config.sh` reads that. ADR-0009 is the decision.
- **`install.sh`**: tools with install hints, clone or link, `~/.local/bin/xal-factory`,
  the plugin, then the onboarding. Works under `curl | bash`.
- **`bin/xal-factory`**: `init` (onboarding; gum if present; `--yes`; `--set k=v`), `seed`,
  `config list|get|set|explain`, `enable`/`disable`, `apply` (GitHub workflows and variables
  to match the conf), `doctor`. Bash 3.2. Checks for a git identity before seeding.
- **`site/`**: Astro 7, Starlight 0.42. `scripts/sync-content.mjs` copies `spec/`, `adr/`,
  `PRINCIPLES.md`, `docs/adopting.md` in at build (gitignored copies, links rewritten);
  `scripts/options-page.sh` renders the registry; hand-written pages are `index.mdx`,
  `install`, `onboarding`, `autonomy`, `faq`. `wrangler.jsonc` deploys a Worker with static
  assets on the custom domain `factory.getxal.com`, which also serves `/install.sh`.
- **Gates:** 11 options registry, 12 installer and CLI end to end, 13 shellcheck (CI only),
  14 the options page names every option. The factory's gate now has 15 gates and 15
  fixtures.

## Not done, and why

- **Nothing has deployed.** `site.yml` deploys on push to `main` once the secrets exist.
- **The pipeline has not run live from a factory-seeded repo.** It ran for weeks in the
  source estate; here it is proven by fixtures only.
- **No tags.** `reader.ref` defaults to `xal-factory--v<VERSION>`, so seeded repos pin
  `xal-factory--v0.2.0`, which does not exist yet. The reader workflow in a seeded repo fails
  until that tag exists.
- **`factory.getxal.com/install.sh` 404s** until the first deploy.

## Known risks to check first

- **npm 11's install-scripts policy** printed a warning that `workerd`'s postinstall was not
  run locally. `wrangler deploy` of a static-assets Worker should not need it. If the deploy
  job fails there, add `npm install-scripts approve workerd` or pin the step.
- **The harness takes about 4.5 minutes** in CI. Acceptable. Speed it up only if it starts
  to block.
- **`site.yml`'s path filter** means a change to the README alone does not rebuild the docs,
  and the README is not a docs page, which is deliberate.
